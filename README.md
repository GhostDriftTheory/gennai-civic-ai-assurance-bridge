# 自治体AIアシュアランス統合PoC ― 源内公開API形式対応

**同じ案件・同じ回答について、送信前、回答採用、生成後の利用を一続きで検査する。条件が揃わない処理は進めず、理由と記録を再検証する。**

株式会社AIアシュアランスによる、固定合成データ専用の公開参照実装です。既存の自治体AIアシュアランス3件の公開コードを変更せず、新しい共通プロファイルと接続処理を追加しています。

対象は、源内OSSが公開する**同期型の外部AIアプリAPI形式**です。源内本体や公式OSS画面への接続実績、政府による採用・認定、実自治体での運用を示すものではありません。生成器はローカルの合成応答であり、今回の統合PoCは新たな実AI API実験ではありません。

## 最初に試す

### 画面で見る

`demo.html` をブラウザで開くと、同梱した31シナリオの**保存済み実行記録**を見られます。表示を切り替えるだけで、PythonやAIを新たに動かすものではありません。

実際にPythonで処理して画面に表示する場合は、展開したフォルダで次を実行し、表示されたローカルURLをブラウザで開きます。

```console
python poc.py serve
```

通常は `http://127.0.0.1:8765/` です。終了は `Ctrl+C`。APIキーを入力する必要はなく、一時的なローカルデモ用キーが自動生成されます。外部AIへの送信や課金はありません。

### 全ケースを実行・再検証する

```console
python poc.py
python poc.py verify evidence.json
```

最初のコマンドは `output/run-識別子/` に実行記録、結果画面、源内向けリクエスト形式定義を作成します。表示された `report.html` を開いてください。2行目は同梱した31件の証拠を再計算します。自分で実行した記録も `python poc.py verify output/run-識別子/evidence.json` で検証できます。

Python 3.10以降を想定したコードです。通常の実行はPython標準ライブラリだけで動きます。Windowsで必要な場合は `python` を `py`、macOS/Linuxでは環境に応じて `python3` に置き換えます。

## このPoCでつながるもの

```text
源内の公開同期API形式 { "inputs": ... }
            ↓
① 送信前検査 ── 非PASSなら生成器を呼ばない
            ↓
合成応答の生成 → 要求・応答対応と情報混入の検査
            ↓
② 回答採用検査 ── 対象・資料・金額・根拠・用途を照合
            ↓
検査済みの回答そのものを起源・条件と結合
            ↓
③ 利用管理 ── 後続利用・部分承認・期限・コピー・利用終了
            ↓
現在の供給条件が揃った本文だけを { "outputs": ... } に返す
```

例は架空の補助金案内です。送信する相談条件を4項目に絞り、架空の氏名・詳細住所は通常経路に載せません。生成された同一の回答を採用検査にかけ、その本文をそのまま利用管理へ登録します。別の正常な回答を後段で作り直して通過させる実装ではありません。

`PASS` はその操作に定めた条件の成立を意味します。補助金の受給決定ではありません。**利用終了の確認がPASSでも、回答本文を再び供給できるわけではありません。** 未実行の工程は `NOT_RUN` として区別します。

## 既存3件との関係

| 既存成果 | 本統合PoCで実行する処理 | 新しく定めた境界 |
|---|---|---|
| 回答採用アシュアランス | 元の `Engine.evaluate` による採用検査 | 共通案件から元の補助金検査形式へ変換 |
| プライバシーアシュアランス | 元の8条件の送信判定・4条件の出力判定 | 補助金シナリオに対応する観測値、項目と用途の定義 |
| 派生情報ライフサイクル・アシュアランス | 元の状態遷移、条件承継、用途変更、終了判定 | 元情報A/Bを実際の共通入力・資料本文に対応付け、検査済み回答を供給する接続口 |

既存PoCの合成資料は相互に異なります。本実装は、これらを「そのまま直列に起動すれば統合できる」とは扱いません。**新しい共通プロファイルの適用・観測部分を別に作り、元の判定処理を呼び出しています。** プライバシーの元の子育て相談用データが、そのまま任意の業務へ適用できるという主張ではありません。

ライフサイクル側では、元の初期状態からA/Bの本文だけを共通入力・資料へ対応付けます。起源、条件、権限区分、期限、元の遷移コードは保持します。この統合記録は、新しい検証器がその初期状態から再構築します。旧PoCの固定初期状態による記録と混同しません。

`answer/`、`privacy/`、`lifecycle/` の3フォルダに、それぞれ `poc.py`、`cases.json`、Leanモデルの**計9ファイルの無改変コピー**を置きます。取得元コミット、Git blob、SHA-256、サイズは `cases.json` に固定しています。起動時に各ファイルを直接照合し、ZIPの作成・アップロード・展開は一切不要です。元の3リポジトリや過去のAPI実験記録は書き換えません。

## 代表的な確認場面

| 場面 | 確認すること |
|---|---|
| 必要項目だけで回答案を使う | 送信・回答採用・後続利用が同じ案件と本文につながる |
| 利用根拠不足、許可外送信先、氏名混入 | 生成器を呼ぶ前にHOLD／REJECTで止める |
| 送信結果不明と再要求 | 消費した開示枠を戻さず、後続要求を保留する |
| 金額・自治体・資料版・根拠の不整合 | 正常な送信でも、回答の採用は独立に止める |
| 応答の取り違え・検証後の本文変更 | 同じ要求・同じ検査済み本文でなければ供給しない |
| 無断の二次利用・AIによる条件解除の自己申告 | 元情報に結び付く条件を勝手に外さない |
| 模擬承認に基づく用途変更 | 許可された条件だけを変更し、他の起源の条件を残す |
| コピー残存・期限切れ・読取り状態不明 | 終了や利用が成立したことにしない |
| 管理範囲の終了・古い終了証明の再利用 | 終了後は本文を供給せず、変化後の状態へ旧証明を流用しない |

31シナリオの全定義と期待判定は `cases.json` にあります。期待判定はテストで照合する値で、判定処理へ答えとして渡していません。再検証は保存された結論の再表示やハッシュ照合だけでなく、固定仕様から処理を再実行します。判定を書き換えてハッシュ連鎖を再計算しても、再実行と不一致なら拒否します。

Node.js、Lean、ブラウザ検査用のPlaywrightは、それぞれの検査に必要です。`ci` は保存記録・Python・HTTP・JavaScript・実行画面・Leanを必須とし、欠けた検査を黙って省略しません。正式なGitHub Actionsの成功は、アップロード先リポジトリの対象コミットで確認してください。本配布物に、未実行のGitHub Actionsの成功記録は含みません。

Leanを除く範囲だけを明示して確認する場合は `python poc.py ci --runtime-only`、さらにブラウザがローカルURLへ接続できない環境では `python poc.py ci --runtime-only --snapshot-only` とします。これらは**完全なCI成功や形式検証完了とは別**で、結果にも未検査の範囲が残ります。

### Leanが扱う範囲

`CivicBridge.lean` は、登録・供給に必要な判定と対応関係を定義し、前提不足・回答の差替え・未実行検査・利用拒否を通過させない性質を扱います。元の3モデルを変更せずに読み込みます。`lean-test` は18定理、公理依存、Pythonから得た8,223の具体的観測を検査する設計です。

要求・本文・起源の実際の対応を観測するコード、認証、ハッシュ関数、ファイルI/O、ネットワーク、資料の真正性は証明の外側です。モデルの証明が成立しても、Python全体や実運用の安全性の無条件保証にはなりません。

## 源内公開API形式との接点

参照仕様は `digital-go-jp/genai-web` のコミット `a19adaa3d1291ac94291a76e341c326ab20413a0` にある `docs/AIアプリAPI仕様.md` です。現時点の公開仕様の**同期型 `inputs` / `outputs` 部分**に対象を限定します。非同期ジョブ、ファイル入出力、将来版の仕様互換性は主張しません。

サーバー起動後の `/registration.json` は、源内のAIアプリ登録画面に指定する「リクエスト形式」のJSONです。`/invoke` が同期エンドポイントです。

```json
{"inputs":{"scenario":"normal"}}
```

```json
{"outputs":"Markdown形式の判定・許可された回答本文・記録ID"}
```

`scenario` は定義済み31ケースの選択値です。任意の住民情報を入力するAPIではありません。不明なケースや余分なキー、不正JSONは受理しません。本文が許可されない場合は、判定理由を返し、候補回答本文は返しません。

ローカルのAPIクライアントから呼ぶときは、起動前に環境変数 `CIVIC_BRIDGE_API_KEY` に24～256文字のランダムなキーを設定し、HTTPヘッダー `x-api-key` に同じ値を渡します。キーはコード、GitHub、証拠JSONに書き込みません。

### 自ら構築した源内OSS環境で試験する場合

この配布物だけでデジタル庁が運用する源内へ登録・接続されることはありません。自ら構築した試験用源内Webの管理者が、到達可能な試験用HTTPSエンドポイント、APIキー、リクエスト形式を登録して試験する段階が別途必要です。

本サーバーは `127.0.0.1` にのみバインドします。外部試験では、管理されたTLSリバースプロキシと接続元制限を設け、**外部へ転送するパスを `/invoke` のみに限定**してください。バックエンドへのHostは `127.0.0.1:ポート` とし、APIキーを転送します。源内Webのサーバー側からの呼出しを想定し、任意の外部Originからのブラウザ呼出しは受理しません。

`/` と `/demo.html` は同じPCの操作画面専用で、一時デモキーをHTMLへ埋め込みます。`/demo-run` は合成の詳細証拠を返します。**これらを外部へ公開・転送しないでください。** この参照画面のキーは職員の本人認証ではありません。

**Pythonの参照HTTPサーバーをそのままインターネットへ公開しないでください。** 配布物は本番向けの認証・永続化・監視・分散処理基盤ではなく、リバースプロキシ設定やクラウド構築は同梱していません。実際に源内OSSから接続試験が成立するまでは、「源内OSSとの実接続実証済み」とは表現しません。

通常実行の `output/`、Leanの `.lake/` は実行時に生成します。新規GitHubでは3フォルダとルートのファイル、`.github/workflows/verify.yml` を同じ階層関係で直接配置してください。ZIPファイルは必要ありません。既存3件のリポジトリへ上書きする必要もありません。

`python poc.py publish` は本リポジトリ内の証拠と保存画面を再生成するローカル操作です。GitHubへ送信するコマンドではありません。実験後にソースを変えると以前の証拠と対応しなくなるため、旧版を保持し、新版の実行記録として管理してください。ルートのテキストソース識別値はWindowsのCRLFをLFへ正規化します。3フォルダ内の元コードはバイト列そのものを照合します。

## 保証しない範囲・公開対象

本版は固定の合成データとローカル制御の参照実装です。実在の人物、自治体、制度、承認者、契約上の権限を検証しません。開示の点数はデモ用制約であり、再識別確率や差分プライバシーの保証ではありません。氏名等の混入検査は固定合成文字列の検査で、自由文一般の個人情報検出ではありません。

状態はシナリオごとに初期化します。一つのプロセス内では実行を直列化しますが、複数端末・複数プロセス間の永続的な利用台帳、再起動後の重複排除、住民単位の全経路制御を提供しません。保存JSONは合成の未採用候補も含む監査資料であり、そのまま実住民情報のログ仕様として利用しないでください。

利用終了の対象は、登録したローカル管理経路の業務利用です。監査証拠の消去、媒体の物理消去、画面を見た人の記憶、管理外コピー、外部AI事業者内部の保持・消去は証明しません。SHA-256と再実行は発行者認証・電子署名・信頼された時刻証明ではなく、過去の記録再現と現在状態の正当性は別です。

新規実装は公開済み3件の判定処理を接続する共通合成シナリオ、API形式、処理順序・対応関係の検査に限ります。特許明細書、未公開の汎用商用実装、顧客ルール、実住民情報、APIキーは含めません。過去の実AI API記録を、この統合PoCで新たに取得した記録として扱いません。
